# App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user arrives at the application by visiting the landing page, which displays a simple welcome message and two prominent buttons labeled “Sign In” and “Register.” When the user clicks “Register,” the app navigates to the registration page. On this page, the user provides an email address, creates a password, and confirms that password. Real-time validation ensures the email has a valid format and the password meets complexity requirements before the user can submit. When the form passes validation, a request is sent to the Golang backend’s register endpoint. On success, the user is automatically signed in and redirected to the main dashboard. If the user already has an account, they can click “Sign In” from the landing page or the header of any public page. The sign-in page prompts for email and password, validates them, and then sends a login request to the backend. A successful login stores the authentication token in a secure, httpOnly cookie and redirects the user to the dashboard. Users can sign out by clicking the “Logout” option in the header, which triggers a logout request to the backend, clears the session cookie, and brings the user back to the landing page. If a user forgets their password, they can click a “Forgot Password?” link on the sign-in page. This takes them to a page where they enter their email. After submission, the system sends a reset email with a one-time link. Clicking that link leads to the password reset page where the user sets a new password, completing the flow by redirecting them back to the sign-in page.

## Main Dashboard or Home Page
After logging in, the user lands on the dashboard, which presents a clean header across the top. The header shows the application name on the left, and on the right, it displays the user’s avatar and a menu with options for profile and logout. A collapsible sidebar along the left side lists navigation links to the Dashboard, Profile, and Settings. In the main content area, the dashboard displays welcome text and summary cards or placeholders that represent key data or recent activity. From this dashboard, clicking any navigation link in the sidebar transitions to the corresponding page without a full reload. The user can always return to this main view by clicking the Dashboard link in the sidebar.

## Detailed Feature Flows and Page Transitions

### Registration Flow
When the user chooses to register, the app navigates to the registration page. The form fields appear in a card centered on the screen. As the user types an email, inline validation flags invalid formats. When the user sets a password, a password strength indicator updates in real time. After confirming the password, pressing the Submit button triggers a client-side validation with Zod and sends a POST request to the Golang `/api/register` endpoint. While the request is in progress, a loading spinner appears on the button. If registration succeeds, the backend returns a JWT in a secure cookie. The app reads a success status, updates the global auth state, and pushes the user to the dashboard.

### Login Flow
On the login page, the user enters their email and password. The app uses React Hook Form to manage input state and display any missing or malformed entries. Submitting the form fires a TanStack Query mutation that calls the Golang `/api/login` endpoint. During this time, the login button remains disabled and shows a spinner. If the backend returns valid credentials, the httpOnly cookie is set, the global auth context updates, and the app navigates the user to the dashboard. If credentials are invalid, an error toast appears at the top of the screen describing the issue.

### Password Recovery Flow
The user clicks “Forgot Password?” on the login page and is taken to a recovery page. They type their email, and the form triggers client-side validation. On submission, the app calls the Golang `/api/forgot-password` endpoint. If the email exists, the backend sends a reset link to the user’s inbox. The app then displays a confirmation message instructing the user to check email. Clicking the link in the email opens the app to the password reset page with a token in the URL. The user is prompted to enter a new password and confirm it. When they submit, a request goes to `/api/reset-password` along with the token. On success, the user is redirected to the sign-in page with a brief confirmation banner.

### Profile Edit Flow
From the sidebar, the user selects “Profile,” which loads the profile page. The page shows the user’s email address in a read-only field and provides editable fields for display name and other personal details. The user can update these fields and click “Save Changes.” The app validates any new input, sends an update request to the `/api/user` endpoint, and then refreshes the displayed data. A toast message confirms success.

### Protected Route Navigation
When the user tries to navigate directly to a protected page via URL, the app checks the global auth state on load. If a valid session cookie is present, the app fetches the user data and renders the page. If the session is missing or expired, the router automatically redirects the user back to the login page. After a successful login, the user is brought back to the initially requested route.

## Settings and Account Management
The Settings page is accessible from the sidebar and carries options to change the user’s password, configure notification preferences, and toggle between light and dark themes. The password change section asks for the current password and a new password with confirmation. When the user submits, the app validates the current password by calling the `/api/change-password` endpoint and updates the stored credentials on success. Notification settings include toggles for email updates or product announcements. Changing these preferences sends a PATCH request to `/api/user/preferences`. The theme switcher updates a theme variable stored in local storage and applies the new style immediately. At any point, the user can navigate back to the Dashboard or Profile using the sidebar links.

## Error States and Alternate Paths
If the user enters invalid data anywhere in a form, inline error messages appear beneath the relevant field. For failed network requests, a toast displays an error summary such as “Server unavailable” or “Invalid credentials.” If the app loses connectivity mid-request, the user sees a full-page offline banner and can retry the action. Attempts to access restricted areas without authentication result in an automatic redirect to the login page. If a password reset token is invalid or expired, the reset page shows an error message with a link to restart the forgot password flow.

## Conclusion and Overall App Journey
A typical user starts at the landing page, signs up with an email and password, and is guided through client-side validations before the backend creates an account. Upon successful registration, they land on the dashboard, where they see navigation options to explore their profile and settings. Daily use involves signing in, viewing or updating personal information, and adjusting preferences. Throughout the journey, protected routes guard sensitive pages and error handling keeps the user informed if anything goes wrong. Logging out ends the session and returns the user to the public landing page, ready for the next sign-in or registration cycle.
